# Implemented protocol (v1)

Actors are deterministic software utilities, each with private reserve, dependency stress, starvation duration, last bid and last commit. No network or learned model is involved. Each tick broadcasts HEARTBEAT and directed BID messages, then each live actor independently clears its received bid set. COUNTER / CONCEDE records the feasible price bound, ACCEPT names the local vector hash, PREPARE exchanges hashes, and COMMIT requires unanimous live hashes plus Constitution validation. The coordinator delivers messages and advances time; the Constitution only returns errors.

Concession is `m + (d-m) min(1,(v/p)^(1+2φ))`, with full demand at p ≤ v. Value is `W (1+2(1-min(reserve,4)/4)) (1+.5 dependencyStress)`. General agents starved below .5 service for >12 ticks receive a 1.5 value factor if a general peer is above .8. No cross-tier transfer is mandated by fairness.

Minimums are clipped by feeders, then reduced in ascending value order (ID breaks ties) until every bus and root constraint is feasible. Each local bus price and root price use a doubling bracket (max 40 expansions) then at most eight bisections per search phase; the upper feasible price is selected. Allocations floor to .01 PU. Tiny residual numerical tails are projected down. Every COUNTER/CONCEDE includes its bus/root phase and the exact feasible upper bound of that iteration. The upper bound may decrease between iterations, so counters can request more power as the feasible interval narrows; the concession curve itself is monotone in price. `trace.rounds` is the maximum count in either phase (≤8), not their sum. Different inboxes can yield different proposals. Approved-plan ticks use `phase=plan` counters with the scheduled allocations, and still require current bids for every managed load before matching hashes.

Every directed BID and PREPARE can be dropped by a seeded bus. A test-only delayed sender is treated as arriving after the barrier. Late bids are discarded; this implementation does not reuse stale bids (a conservative simplification of the optional two-tick cache). Missing bids produce different full allocation vectors, including zeros for unknown loads. On failure ABORT is emitted, all bids rebroadcast once, then the previous committed vector is projected by value-ordered shedding. Unmanaged demand draws first, proportionally scaled to bus/root caps; crashed agents hold their prior draw clipped to remaining constraints. Their absence removes them from the live set immediately; DOWN becomes visible after two missed heartbeats. Rejoin uses a fresh BID. No freed power is invented after projection.

I1 supply, I2 buses/feeders, I3 bounds, I4 reserve, I5 unanimous negotiated commits, I6 feasible fallback and I7 deterministic replay are tested. I5 cannot literally require unanimous COMMIT for an abort fallback: the architecture's explicit fallback and baselines are named exceptions. Applied violations remain zero; blocked counts count failed physical proposal checks, not ordinary message timeouts. Tolerance is 1e-7 PU; hashes use integer hundredths and stable ID order (FNV-1a, an identity checksum, not cryptographic security).

A normal trace is HEARTBEAT → directed BID → each actor's COUNTER/CONCEDE → ACCEPT → directed PREPARE → COMMIT. Injecting a drop produces the same sequence ending ABORT, another attempt ending ABORT, then `outcome=fallback` with its applied hash. The UI renders these messages directly, including delivery status. `experiments/results/crisis_trace.json` records a measured crisis tick after batch execution.
